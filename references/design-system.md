# Modern 95 UI 设计规范

## 优先视觉：任务工作台

任务工作台优先采用 Handover 案例的窗口外框、标题栏与右上角窗口控制组。以下规则供不同项目与框架接入；已有项目的局部修改只覆盖请求范围。

- **整体分区：** 一条深蓝应用标题栏统领页面，浅灰外框和工具区包围白色或近白工作面。用连续细边框、共享分隔线和整齐留白区分区域，减少嵌套卡片、重复边框和装饰性标题条。
- **标题栏层级：** 左侧为白色线性应用图标与醒目名称；右侧可放较轻的上下文文字，再接窗口控制组。两端文字与按钮组垂直居中，长上下文优先收缩或省略，保留应用身份与可操作按钮。
- **右上角控制组：** 最小化、最大化／还原、关闭的常态按钮采用比标题栏略亮的同色系蓝底、细浅色边框、克制内高光和白色线性图标。三者等大、等距、小圆角，图标视觉居中，按钮上下留白一致。它们应像标题栏的一部分；这一位置优先于旧案例的浅灰凸起按钮。关闭键常态与其他两键同组配色，危险反馈按平台交互约定处理。
- **页面头部与工作区：** 页面标题和简短路径信息放在标题栏下方；语言等页面级选择器与其分列，标签紧邻控件。任务型工具可用左侧选择／操作区和右侧当前选择／预览区，主要动作靠近它作用的输入，底部状态栏保持轻量。按流程分配空间：向导可舒展，账目表格继续紧凑。

实现窗口控制时沿用宿主已有的窗口能力与关闭保护。普通网页没有对应窗口动作时省略相关按钮；静态演示明确标注其性质。正常、悬停、按下、焦点和禁用状态按目标平台补齐并验证，截图只确认已展示的外观。

Handover 中的标题栏参考参数：

- 标题栏最小高度 34 CSS px、内边距 3 px；窗口按钮 32 × 28 CSS px、间距 3 px、圆角 3 px。
- 按钮常态底色 `#243b84`、1 px 边框 `#6d80b6`、白色图标，内高光 `inset 0 1px #ffffff20`。
- 悬停底色 `#3a5092`；按下使用内影 `inset 0 1px 3px #0004`；键盘焦点为白色内缩轮廓。关闭键悬停为 `#a33747` 底、`#c67d87` 边。

这些是优先视觉的参考实现值，具体控件在目标项目中验证；共享的 30 px 控件、4 px 圆角等数值令牌保持原样。浏览器参数与真实系统 DPI 分开记录，证据范围见 [验证说明](../docs/validation.md)。

[Handover desk](../assets/design-lab/dist/workbench.html) 是按这些规则编写的合成浏览器案例，可通过本地服务打开，展示同色系标题栏按钮、灰白双栏和连续的分组列表外框。按钮的名称与页面说明明确其仅操作预览区域；真实产品使用宿主窗口能力。

## 基线参数

`assets/tokens.css` 保存已确认的数值基线。任务工作台与 Starter 共用这组配色和基础几何；已有项目字体或开发者明确选择优先。

安装版本以 `SKILL.md` 与 `package.json` 为准；令牌注释中的 `0.1.0` 和日期标识数值基线，优先视觉日期标识外观选择。文档迭代可升级安装版本而保留原令牌。

| 项目 | 当前值 | 用途 |
| --- | --- | --- |
| Desktop | `#008080` | 应用窗口周围的桌面背景 |
| Title | `#102776` | 标题栏、主要操作、选中强调 |
| Chrome | `#eef0ed` | 工具栏、窗口框架、次要按钮 |
| Typeface | `Segoe UI` | 未指定字体时的推荐默认；开发者可替换 |
| Base size | `14 px` | 案例信息密度参考，按项目内容与可读性调整 |
| Density | `compact` | 普通控件 30 px、表格单元格上下 9 px、主要内容留白 16 px |
| Borders | `defined` | 外边框 `#89979b`，通常 1 px |
| Depth | `raised` | 轻微内高光、下缘暗线和浅阴影 |
| Corners | `4 px` | 控件、面板和状态标签的小圆角 |

辅助颜色：正文 `#222f33`、次要文字 `#58676c`、内部细分隔 `#e1e7e4`、内容纸面 `#ffffff`、表头 `#f3f5f2`、表尾 `#fafbf9`。强边框用于容器和控件，内部行分隔更轻。

凸起控件：`inset 1px 1px #fff, inset -1px -1px #9aa5a6, 0 1px 2px #1e303328`。
应用窗口：`inset 1px 1px white, 0 8px 28px #003b3b40`。
主要按钮采用深蓝底、白字和弱内高光；不要叠加灰色按钮的全部斜面。

## 字体默认与覆盖

新项目未指定字体时，使用 `"Segoe UI", sans-serif`；缺失时采用系统无衬线回退，包内不附字体文件。现有项目沿用其字体方案，开发者可按平台、语言和品牌调整 family、字号、字重、回退及静态／可变方案。14 px 是案例密度起点。

使用基础令牌时可在项目主题容器上覆盖 `--font` 和 `--font-size`，Starter 对应 `--m95-font` 和 `--m95-font-size`；原生应用使用框架的字体配置。更换后检查实际文本的对齐、层级、换行与裁切；字体替换无需更新共享视觉基线。

## 视觉结构

独立设计实验室可展示：桌面 → 浅灰应用外框 → 深蓝标题栏 → 工具/导航区 → 白色工作内容 → 轻量状态栏。

真实桌面产品先确定由系统外壳还是自绘外壳承担窗口职责，只保留一套标题栏、窗口边界及操作组；使用系统外壳的回退模式同步隐藏模拟外壳。青绿桌面属于展示场景，嵌入 WebView 时按宿主去除模拟桌面留白。自绘外壳的动作、缩放及关闭保护见 [原生桌面规范](native-desktop.md)。

标题栏表达当前应用或区域；不要给每个卡片再套一条深蓝栏。一个页面有一个清晰的主要动作，次要动作与筛选使用更低视觉重量。偏向稳定、紧凑的工作台，不把通用仪表盘的巨大数字卡片、渐变和胶囊按钮作为默认组成。

标题、正文、标签和辅助文字保持清晰层级；具体字体、字重与字号由项目开发者选定。窄侧栏中的小字需实际检查可读性；触屏产品可提高密度，不将桌面的 30 px 控件当作通用触控目标。

编号和金额使用稳定的列对齐；项目字体支持时，可用 `font-variant-numeric: tabular-nums` 辅助金额对齐。

## 工作台文案

- 页面优先呈现标题、导航、数据和动作。标签已说明用途时，省略复述功能的副标题或介绍段落；保留帮助用户判断当前任务、对象或范围的上下文。
- 流程条用于实际分步任务，表达当前步骤或进度；仅把已有分类按顺序再列一次的装饰性流程条省略。
- 空状态给出必要的下一步，例如 `Select a document`。首次配置或无权限等特殊状态说明具体条件和处理办法。
- 帮助文字提供新增信息：输入格式、适用条件、错误原因、处理办法或有实际影响的操作后果。控件标签与可访问名称保留。
- 删除说明时同步收起专属容器、边框和留白，让列表与操作区自然上移；保留相邻区域所需的分隔。
- 涉及共用日期、作用对象或保存范围的说明属于操作信息。压缩介绍段落时，将这类信息移到对应控件或组标题旁，再检查用户能否判断一次操作影响哪些内容。

## 表格和工具栏

- 文本列左对齐，金额列的表头与值共享右边线；同一列的内边距一致。不要凭字符串长度添加空格对齐。
- 总额、余额、日期和普通文字维持清晰层级。状态标签用文字加浅色底：Paid 绿、Partially paid 黄、Issued 蓝灰。其他业务状态按含义映射，不借颜色暗示错误业务状态。
- 搜索框、筛选和按钮检查文字基线及可见高度。不同字体天然字形边界可不同，优先统一 line-height、padding 和父容器对齐，避免逐项加 transform 补丁。
- 窄屏在表格内部横向滚动，保留列的可读宽度；滚动区域有名称且能获得键盘焦点。页面本身不应被整张表格撑宽。
- 滚到末列时仍能辨认当前行的对象。按项目选择固定标识列、重复简短标识或可见详情上下文，并检查其占用及遮挡；末列可达与对象可辨分别验收。
- 长客户名允许换行或使用可访问的完整内容入口；不为视觉整齐截掉关键金额。

### 分类与筛选切换组

先判断切换的含义，再决定外观与交互：

| 角色 | 例子 | 适用方式 |
| --- | --- | --- |
| 分类／筛选 | All documents / Receipts / Invoices | 筛选同一结果集，使用下述组样式 |
| 二级导航 | Overview / History | 切换内容面板，沿用导航或标签页语义 |
| 流程步骤 | Select / Review / Export | 表达先后与完成条件，显示当前阶段及可达步骤 |

只有分类／筛选采用本节的统一组外观；保留导航的层级与流程的阶段含义。

- 整组常态使用一致的浅灰底、细边框和控件尺寸。选中项用浅蓝灰底、深蓝文字及轻微内凹区分，避免只有选中项套上凸起按钮、其余项成为裸文字。
- 切换前后保持字重、边框宽度、内边距和高度稳定；具体字体与参数由项目选定。
- 悬停与选中分别表达；键盘焦点使用独立轮廓，并为横向滚动容器内的轮廓留出空间。保持现有控件语义与键盘路径。

接入时检查常态、选中、悬停和键盘焦点，核对切换前后尺寸以及窄窗口末项可达性。颜色从项目主题取值；项目具体色值与尺寸属于组件方案，不新增全局令牌。[Starter](starter.md) 提供这组规则的可运行实现。

### 业务等级与交互状态

业务等级、是否选中和是否聚焦是独立信息。已有颜色、图形或文字表达等级时，先核对业务含义与用户选择，再决定是否统一外观；用文字保留含义，并让选中标记与键盘焦点各自可辨。悬停和按下采用保留语义色或中性交互面，须明确一种策略并检查摘要与控件表达一致。

非业务绑定的设计示例：维护请求使用 `Routine` / `Priority` 两个互斥等级，项目已选择让 Priority 的语义强调更强。等级文字始终保留；选中增加独立标记，焦点另加轮廓。以下是接入验收示例，未新增案例组件或全局色值。

| 状态 | 未选中项 | 已选中项 |
| --- | --- | --- |
| 常态 | 两级含义可辨 | 等级含义与选中标记可辨 |
| 悬停 | 提示可操作，保留等级文字 | 悬停后仍能识别选中 |
| 按下 | 短暂按压反馈，按原交互规则提交 | 保留原有切换／取消语义 |
| 禁用 | 可读且不可激活 | 显示已存选择及不可修改状态 |
| 键盘焦点 | 独立轮廓定位当前控件 | 轮廓与选中标记同时可辨 |

切换后核对摘要等级，移出／取消后核对状态恢复；各态保持外形与文本位置稳定。

## 表单和弹窗

- 标题、字段标签和输入框共享左边线；底部主要按钮右缘与字段右缘一致。参考弹窗使用统一 `--dialog-inset`：普通 20 px，窄屏 16 px。
- 普通输入、select、主要按钮在同一密度下保持相同可见高度。参考样式通过 `padding-block:0; line-height:1.3` 避免原生输入框额外增高；日期和选择控件需在目标浏览器检查。
- 等高检查覆盖真实业务行及其派生样式，记录渲染后的顶部、底部和高度。根据字体行高、边框和缩放调整内边距，状态切换时保持尺寸稳定；不同控件可以使用不同 padding。
- 错误信息紧邻字段，空错误槽不占额外间距；错误出现后中部可滚动，操作区仍可达。错误、禁用、hover、active 和 focus-visible 单独验证。
- 首开焦点落在有效工作控件而非关闭按钮；Esc 只关闭最上层，关闭子层后回到合理触发点。模态改样式时保留原有取消、验证和保存锁。
- 业务选中、实际焦点和焦点提示分别表达。优先沿用框架的 focus-visible／输入方式机制，键盘操作始终有清晰定位；鼠标与键盘交替操作时，保留真实焦点、遍历顺序及编辑框选区。具有取消语义的组件检查选中、同项取消和切换，程序化赋值遵循原有规则。
- 用户输入保留原始编辑文本，例如 `100` 不自动补成 `100.00`。列表或正式单据按产品的金额规则格式化；样式改动不碰数值精度、税务计算或提交内容。

## 圆角、边线和图标

有圆角的父面板负责外轮廓，不透明首尾子区背景遵循内圆角：外圆角减去实际边框宽度，下限为零；1 px 边框时为 `max(0px, calc(var(--radius) - 1px))`。只给首个工具栏的上角和末尾底栏的下角赋值。折叠列表的末行关闭时，末尾背景是 summary；展开后检查真正位于底部的内容区，并覆盖 hover、selected、disabled 等背景状态。

直角子背景盖住父圆角会造成表尾断角。不要用全局 `overflow:hidden` 修补；这可能裁掉焦点轮廓或改变滚动。检查 0、4、6 px，角应连续，边线粗细应一致。

内高光和内影沿外轮廓内缩后的连续圆角表达层次，与外边框、外投影分开。检查圆角切点连接及四边外边框的视觉重量，避免高光侵入轮廓或底部出现脱离轮廓的横线。按下态沿同一内轮廓变化；修光影时保持既有圆角、控件尺寸与内容位置。

图标使用统一尺寸和描边语言，参考常规图标 17 px、1.5 px 描边。保持图标/文字的视觉居中；使用项目既有图标库，不为复古感混入像素图标或表情符号。

包内工作台使用固定提交的 Lucide SVG 子集，见 [第三方声明](../THIRD_PARTY_NOTICES.md)。复用相关模块时保留相邻的完整 `LICENSE` 和 `manifest.json`；上游绘制元素保持原样。工作台适配器用 viewBox 和描边缩放保留右上角图标的视觉尺寸及最小化横线位置，按钮 CSS 不变。目标项目可继续采用自己的图标库。

检查可见笔画相对按钮正面的视觉中心，尤其是带下沿阴影的箭头按钮。方向图标保持镜像和一致描边；字形尺寸不稳定时改用轮廓可控的图标。确认偏差后可作随缩放一致的组件级微调，记录前后效果；补偿量只属于该组件。

## 分组列表的外框与首尾

先区分末行选择器未命中和子背景盖住圆角。`:last-of-type` 按元素标签类型匹配：同一父级末尾的 `details.sources` 会使前面的 `.group:last-of-type` 无法匹配。优先让独立业务容器持有完整外框，行只画内部分隔线；来源、帮助或操作区放在该容器之外。

```html
<div class="group-list">
  <details class="group"><summary>Group A</summary><div class="group-content">…</div></details>
  <details class="group"><summary>Group B</summary><div class="group-content">…</div></details>
</div>
<details class="sources"><summary>Sources</summary>…</details>
```

```css
.group-list {
  --list-edge: 1px;
  --inner-radius: max(0px, calc(var(--radius) - var(--list-edge)));
  border: var(--list-edge) solid var(--edge);
  border-radius: var(--radius);
  background: var(--paper);
}
.group-list > .group { margin: 0; border: 0; background: transparent; }
.group-list > .group + .group { border-top: var(--list-edge) solid var(--edge); }
.group-list > .group:first-child > summary {
  border-top-left-radius: var(--inner-radius);
  border-top-right-radius: var(--inner-radius);
}
.group-list > .group:last-child:not([open]) > summary,
.group-list > .group:last-child[open] > .group-content {
  border-bottom-left-radius: var(--inner-radius);
  border-bottom-right-radius: var(--inner-radius);
}
```

示例要求 `.group` 是容器内直接业务行，`.group-content` 是展开行最后的内容区；接入既有页面时限定主题作用域。其他子节点存在时明确首尾业务行，不按标签类型猜测。零行按实际数据数量隐藏或不渲染外框；模板空白文本可能使 `:empty` 无法命中。

局部验收覆盖多行折叠、末行展开、单行、零行、末行悬停／键盘焦点，以及列表后有同标签来源区并展开的情况。检查底边闭合、展开内容包含在外框内、四角连续与焦点可见；范围止于受影响组件。

## 其他内容结构

- **Mail：** 导航、消息列表、阅读区域具有清楚层级；正文有舒适行距。窄侧栏的姓名与地址分层，地址可省略，但完整地址需有可访问的查看路径。
- **Library：** 卡片采用纵向 flex，缩略图固定高度且不收缩，信息区填满剩余空间；长短标题并存时，缩略图顶端、标题起点、元信息底线分别对齐。完整标题优先于统一行数。
- **Planner：** 日期、时间、事件标题各有层级；短事件减少辅助内容但仍有详情入口。周视图内部滚动，窄屏可提供议程视图；不要强行挤扁所有时间列。

## 既有组件的换肤边界

接入已有任务列表、表格或编辑器时，先记录原有操作、数据生命周期及库版本，再用同一组数据比较换肤前后。上游行为、测试接线错误和样式回归分别归因。

- **运行时样式归属：** 查看脚本设置的内联 `display`、尺寸和状态类。业务代码管理隐藏／显示时，可在内部增加布局容器；不要用强制 `display:flex !important` 让空状态控件重新出现。改为 flex/grid 后也检查遗留浮动和 clearfix 伪元素。
- **按下期间的命中：** 检查 `:active` 的选择器优先级及最终计算样式。记录 pointer down 前、按住时、释放后的控件位置；允许约 1 CSS px 的视觉按压反馈，命中区域与布局须稳定。完成一次真实点击并核对结果，截图和脚本直接调用回调不能覆盖这一检查。
- **配置也是交互：** 自定义工具栏时保留动作名称、快捷键、可访问名称、模式中可用性和既有焦点策略。逐一验证进入与退出预览、分栏和全屏，以及禁用操作是否确实不改数据。仅绑定相同回调不足以保留这些行为。
- **界面与文档分开：** 标题栏、工具栏和应用标题使用主题规则；编辑正文、Markdown 预览、代码区和虚拟滚动器保留各自排版语义。内容区有意换风格时单独指定，避免主题容器内的宽泛 `h1`／`pre` 规则顺带改正文。优先用库的公开尺寸选项建立滚动边界。
- **模式容量：** 分栏验收同时检查两侧实际可读宽度和长内容末项；按任务选择堆叠、单栏切换或内部滚动。全屏工具栏换行后，复核编辑区起点及退出路径。具体断点、面板宽度和编辑器高度属于项目变体。
- **找到实际样式边界：** 选择库生成的可见控件测量密度，隐藏的原生输入框不能代表它的尺寸。检查挂在 `body` 的弹出层、Shadow DOM 和 iframe 是否继承主题；隔离的内容通过组件公开样式入口适配。沿用项目字体，分别检查主控件与展开层。
- **检查完整绘制状态：** 改底色时同时核对文字、伪元素、SVG 和背景图标。只需换底色时优先使用 `background-color`，避免 `background` 简写清掉图标。悬停、选中、焦点和校验错误分别检查最终计算样式；错误文字出现后仍需核对字段本身。编辑正文单独指定纸面背景，工具栏及浮动操作区留出实际占用空间。
- **尊重尺寸与内容所有者：** 图表、画布、地图及编辑器优先通过公开宽度／重排选项响应容器变化。检查重排后的实际绘制与操作，不能只看外框宽度；文档渲染器给出的金额／数字对齐也应保留。按组件实际语义分别验证数据、可见标签／详情及容器几何。

按受影响组件选用这些规则；各库的具体选择器、补丁和尺寸保留在项目适配层。

## 有界验证

按受影响结构选用 980、640、375 CSS px 和实际项目常用窗口。对共用令牌的修改至少跨一个表格/表单案例和一个卡片/长文案例。局部圆角修复无须重测全部业务流程。

改动字段宽度、密度或滚动结构时，以真实内容长度和实际容量检查整页，包括主／二级导航、摘要、末行末列及操作区。紧凑布局保留为命名项目变体；用布局分配空间，保留必要滚动和可读字号。测试样本数量仅代表布局工况。

测量相同设计边线的坐标差，约 1 CSS px 的子像素差可结合截图判断。检查真实绘制结果、长英文文本、错误换行、焦点轮廓、滚动末项、底部按钮和金额完整性。声明颜色对比问题时测量实际前景与背景；声明系统 DPI 通过时必须有对应环境证据。

异步搜索、动画关闭和编辑器模型同步分别等待其可观察的完成状态，再执行下一步。记录数据已提交、画面已收起和焦点已恢复的区别；同一失败同时出现在对照与换肤版时，先检查宿主接线和测试时序。快速事件仍不稳定的路径单列限制，不用放慢一次测试宣称已修复。

整应用适配选一条贯穿导航、编辑、确认和持久化的真实工作流：取消核对原数据不变，保存核对记录与归属，刷新及正常关闭重开核对数据仍可用。编辑后立即退出也应遵守草稿保护；保护判断使用当前修改状态，不依赖稍后才同步的界面标记。改了标题栏或控件顺序时，键盘测试核对焦点包含、合理遍历与返回目标，避免把原版固定的 Tab 次数当作唯一正确顺序。应用专属修复留在应用中。
